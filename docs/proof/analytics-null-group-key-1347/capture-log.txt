Visual proof capture: issue #1347, PR #1351
Captured 2026-08-29 against the demo box, on real demo data.

WHAT WAS RUN
------------
Two control-planes, against two copies of the same data, so the only variable
is the fix:

  live control-plane  = the deployed binary at commit 2bad54d37, unfixed,
                        reading the live database.
  cp1347              = this branch, built on the box, reading a pg_dump
                        restore of that same live database taken minutes
                        earlier. Its Redis and its database are its own, and
                        its payment and FX credentials were stripped from its
                        environment, so no background worker of it can touch
                        live state.

Two console containers, identical except for which control-plane they call:

  console1347b -> live control-plane (the before capture)
  console1347  -> cp1347 (the after capture)

Signed in as qa-tester@hive.test, the owner of the workspace whose overview
card was returning the 500. The session was minted through the admin
one-time-token flow in apps/web-console/tests/e2e/support/live-auth.mjs. No
password was set, reset or rotated, and nothing was written to the live
database by this capture.

API key ids are truncated to eight characters here. They are row identifiers
rather than credentials, but there is no reason to print more of them than
the point requires.

The unattributed bucket is 14 requests with zero errors. Those are the rows
that took the whole summary down: ordinary chat completions served to this
workspace through a signed-in session, which carry no API key at all.

ANALYTICS PAGE, GROUPED BY API KEY
----------------------------------
Screenshot analytics.png, captured after the console change on this branch.

The usage chart carries a bucket labelled unattributed alongside the API key
UUIDs, which is the explicit bucket this fix introduces.

Top API keys by spend, row 3, reads:

  3  Unattributed                                    no key    $0.000481

Before the console change in the second commit on this branch, that same row
read "Deleted key" with the suffix "unattrib", because the widget labels any
group key missing from the account key list as a deleted key. No key was
deleted here. That spend is console and chat traffic that never carried a key,
so the old label asserted something untrue about the account.
