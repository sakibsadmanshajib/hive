Why a throwaway stack and not the usual shared one: the SUPABASE_DB_URL in the
shared checkout's .env points at a hosted Supabase project that no longer
resolves. A direct libpq connection to it returns

  FATAL:  (ENOTFOUND) tenant/user postgres.<project-ref> not found

which is a deleted project, not an exhausted connection pool. The earlier
attempt on this PR was diagnosed as shared-pool exhaustion; it was not, and
waiting for that pool to free up would never have produced a render.

Every container, network and volume created for this capture is torn down at
the end of the run.


SEED DATA
=========

Synthetic, written directly into the throwaway database. 410 request_attempts
and 410 completed usage_events on one account, split into two equal windows so
the prior-period deltas have something real to compare against:

  period      events  input_tokens  output_tokens  cache_read  cache%   USD
  prior 7d       170        317,765         68,000      63,261   19.9%  1.07
  current 7d     240        540,500         96,000      88,418   16.4%  1.69

Requests are spread EVENLY across each 7-day window on purpose. That matters
for reading the sparklines below: the true shape of this account's traffic is
flat, so any non-flat sparkline the page draws is an artifact of how the
sparkline is sourced, not of the data.

Three API keys ("Production gateway", "Staging gateway", "Nightly batch job")
carry a 60/30/10 share of the traffic, so the Top API keys panel has a real
ranking to render.

## 03-window-prototype-crash
URL: http://localhost:3276/console/analytics?window=toString
HTTP status: 500
screenshot: 03-window-prototype-crash.png
Page text: "Something went wrong on this page. The rest of the console is
unaffected. Try again, and if it keeps failing, contact support and quote
reference 4020607265."

Browser console:
  [error] Failed to load resource: the server responded with a status of 500
          (Internal Server Error)
  [error] Error: Minified React error #441

This is a live reproduction of a defect this PR introduces, captured on the
same stack as the two working screenshots above. `window` is read straight off
the query string with no allowlist (page.tsx: `const timeWindow =
params.window ?? "7d"`), and the new code then does a plain object lookup on
it. `"toString" in ANALYTICS_WINDOW_SPAN_MS` is true, because `in` walks the
prototype chain, and `ANALYTICS_WINDOW_SPAN_MS["toString"]` is a function,
which is truthy, so `priorPeriodBounds`'s `if (!spanMs) return null` guard does
not fire. `new Date(now.getTime() - <function>)` is an Invalid Date and
`.toISOString()` on it throws a RangeError, outside any try/catch, which
rejects the outer Promise.all and takes the whole server component down.
`constructor`, `valueOf`, `hasOwnProperty` and `__proto__` all do the same
thing.


WHAT THE SPARKLINES ACTUALLY SHOW
=================================

On 01-overview-7d.png the sparklines on Total requests, Input tokens, Output
tokens, Total spend and Cache hit rate are flat at zero across roughly the
left seven eighths of their width and then rise steeply at the right edge.

The seeded traffic behind them is uniform across all seven days. The hockey
stick is not in the data. It is the 100-row page cap: fetchCacheSample asks
for CACHE_SAMPLE_LIMIT=100 rows and the backend serves them
`ORDER BY created_at DESC` (apps/control-plane/internal/usage/repository.go),
so the sample is the most recent 100 of the window's 240 requests, all of them
clustered in the newest third of the window. bucketByTime then spreads those
100 rows across the full seven-day span, and the six or seven buckets with no
rows in them render as a real, measured zero.

The cache-hit tile does disclose its sample, in words, on the tile. The
sparklines do not: four of the five sit next to a headline number that IS a
full-window server aggregate (240 requests, 540,500 input tokens, $1.69), and
they carry no caption, no tooltip and no accessible description, because the
wrapper is aria-hidden.

Also visible in the same screenshot: the Blended price / 1M tile has a delta
but NO sparkline, so five tiles carry one, not the six the PR description
claims.
