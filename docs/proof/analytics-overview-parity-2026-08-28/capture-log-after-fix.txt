Visual proof, post-fix: PR #1276, analytics overview parity.

Companion to capture-log.txt in this directory, which is the PRE-fix capture
the review was written from. This one is the same page, on the same seeded
account, captured after the fixes on this branch, plus a control capture of
the pre-fix build running against the very same stack and the very same rows.

Captured 2026-08-29T01:35Z against a LIVE stack. Nothing below is a fixture, a
mock server, or a stubbed control-plane response. The account's usage rows are
synthetic and were written straight into a throwaway database; every layer that
reads, aggregates, serves and renders them is the real one.

SEED DATA
=========

Synthetic, written straight into the throwaway database as request_attempts and
completed usage_events on one account:

  period      events  spacing   input_tokens  output_tokens  cache_read
  prior 7d       170  59 min         306,000         64,600      51,000
  current 7d     240  42 min         480,000         96,000      96,000

Every row in a period is identical and the rows are evenly spaced, on purpose.
The true shape of this account's traffic is FLAT, so any trend the sparklines
draw is an artifact of how they are sourced rather than of the data. The cache
hit rate is a constant 20 percent (400 cache-read tokens against 2,000 prompt
tokens on every current-period row), so its true trend is a horizontal line.

240 requests is deliberately above the usage-events page cap of 100, so the
sample the sparklines are built from is the most recent 100 rows and not the
whole window. That is the exact condition that produced the reported defect.

Sparkline curves, read out of the rendered SVG (the `d` attribute of each

  curve 2 (input tokens):   28.00 23.67 19.33 15.00 2.00

ceiling, for a rate that never moved off 20 percent.

  curve 2 (input tokens):   2.00 3.00 4.00
  curve 3 (output tokens):  5.47 6.33 7.20
  curve 4 (total spend):    4.34 5.25 6.16
  curve 5 (cache hit rate): 2.00

Read those against the control above. Nothing touches the baseline any more,
and no curve crosses more than about 1.6 px of a 28 px chart. The cache hit
rate curve, whose true value never moves, is a single y value: exactly flat.

The residual ripple on the other four is real and is not a defect. The sample
is 100 rows spread over its own real span, cut into 8 buckets, and 100 does not
divide by 8, so consecutive buckets hold 12 or 13 requests. Recharts scales
each sparkline to its own min and max, so a difference of one request fills the
chart height. The tile is a shape indicator next to a headline number, and the
shape it now indicates is the sample's own distribution rather than an artifact
of the page boundary.

Each sparkline also carries a visible caption naming its sample ("Trend across
the last 100 requests"), and its wrapper is role="img" with that same text as
its accessible name. In the control capture there is no caption on any tile and
the wrapper is aria-hidden, so the bounded sample was disclosed in no modality
at all.
