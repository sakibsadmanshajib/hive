IDENTITY
========

Native Open WebUI sign-in is deliberately Caddy-blocked on this deployment's
Caddyfile.owui (POST /api/v1/auths/signup and /auths/signin both answer 404 by
design, SSO-only posture), and the throwaway GoTrue stood up above is not
registered as this stack's OAuth provider (that would need extra GoTrue OAuth-
server configuration out of scope for a label-only PR). Signing in through
either path was not attempted.

Instead this used the same audited mechanism scripts/owui-mint-admin-token.py
documents for exactly this situation (issue #556): a short-lived (5 minute)
Open WebUI session token, minted inside the open-webui container from its own
WEBUI_SECRET_KEY, for an account inserted directly into that container's own
sqlite database (id 450cd9c8-0450-4a30-86dc-33adea9d2e53, role admin, email
work-label-capture@hive-local-capture.invalid). This is Open WebUI's own
internal auth database, entirely separate from the throwaway Supabase/GoTrue
stack above; no password was set anywhere, no shared or pre-existing account
was touched, and the throwaway database this account lives in was destroyed
immediately after capture. The token was injected via Playwright's
context.addInitScript (localStorage.token), never placed in a URL, so no
capture below carries a credential in its query string and none needed
redaction.

* 11-composer-work-toggle.png - chat home, Chat mode selected. The composer

  The internal data-hive-mode values are unchanged ("chat" / "cowork"), per
  the brief's prohibition on renaming wire-level identifiers.
* 12-work-mode-selected.png - the Work segment clicked. The pack row welds in
  below the composer exactly as it did as "Cowork" mode (Knowledge work |
  Coding, "Runs in a sandbox. Progress appears in this conversation."),
  confirming the mode-toggle rename did not touch ComposerCoworkRow.svelte,
  the .hv-cowork-* CSS classes, or the sandboxed-run behavior itself, only
  the visible label.

blank-instructions refusals) are unit-tested in

apps/web-console/tests/e2e/_probe/agent-workspace-flows.spec.ts (see the PR
body's test list); they were not separately screenshotted since they are
