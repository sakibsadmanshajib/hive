# Issue 1358, a project's files reach a conversation in that project, captured 2026-09-02

## Substrate, stated plainly

The chat image built from this branch (`hive-owui:proof-1358-final`, built by
`deploy/docker/Dockerfile.open-webui` from commit `0d2e8c3`) running as a single
container on `http://127.0.0.1:13580`, with a fresh database and no prior state.

It is not the deployed box, because the deployed box serves `main` and this
change is not merged. It is not the full compose stack either: the paths under
test are the frontend's request assembly and Open WebUI's own retrieval, both of
which live entirely inside this container. What the container is missing is the
Hive gateway in front of the model and the embedding call, so both are pointed
straight at OpenRouter for this capture, at the same model and the same
embedding model `deploy/litellm/config.yaml` routes to on the deployment
(`dots-studio/dots-3-note-preview:free` and
`nvidia/llama-nemotron-embed-vl-1b-v2:free`). Nothing in the diff touches
billing, routing or the gateway boundary, so that substitution changes nothing
this capture claims.

`WEBUI_AUTH=false`, so the run needs no identity at all. No shared test account
was used, and no password was set, reset or rotated.

## Redaction

Nothing to redact. Every URL recorded below is a bare path on `127.0.0.1`, no
flow in this capture carries a credential in a query string, and the instance
runs with authentication disabled so no session token exists to leak. The
identifiers in the log are project, file and chat UUIDs generated by this
throwaway container, not credentials.

## The fact, and why the answer can only come from the file

The document contains one string that exists nowhere else, `BRACKEN-7741-QX`,
presented as the rack asset tag of the Hive demo box. It is not in any model's
training data, not in this repository, and not anywhere else in the container.

## Control first, before the project exists

The control turn runs on a fresh instance that holds no project and no document
at all, so there is nothing for the model to find by any route, including the
knowledge search tools it reaches for on its own.

```

/api/chat/completions model=dots-studio/dots-3-note-preview:free files=null
```

The model searched, found nothing, and said so: "I've searched through the
available knowledge bases and previous chat conversations, but I couldn't find
any information about a Hive demo box or its rack asset tag."

The conversation renders "Retrieved 1 source", answers "The rack asset tag of

`rack-register.txt`.

## What the two `files` lines are, and why they are the load bearing evidence

The screenshots show the outcome. The two lines above show the mechanism, read
off the outgoing request rather than inferred from it:

* control, no project: `files=null`, which is the state every conversation in a
  project was in before this change, marker or no marker;
* in the project: `files=[{"type":"collection","id":"<the project>"}]`, put
  there by `withProjectFiles` at the request assembly in `sendMessageSocket`.

A conversation created inside a project also opens at all now, which it did not
before: `/chats/new` stored the marker alone, and `loadChat` then called
`convertMessagesToHistory(undefined)` and threw before the page rendered.

```bash
  -e RAG_TOP_K=5 -e WEBUI_SECRET_KEY=<secret> -e ENABLE_TITLE_GENERATION=false \
  hive-owui:proof-1358-final

# New chat, ask, read the intercepted request bodies
```
