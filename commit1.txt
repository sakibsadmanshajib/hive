    test: make the live OpenAI conformance suite measure the gateway rather than itself
    
    The first real run of this suite (33210676196) failed eleven assertions. Three
    were the suite being wrong about its own subject, one was a cost defect in the
    suite, and the rest were genuine gateway gaps that now have issues and stay
    asserted rather than deleted.
    
    Suite defects, fixed here.
    
    max_tokens was asserted as a flat ceiling on completion_tokens. That is not the
    contract on a pooled alias: edge-api deliberately inflates the upstream ceiling
    by the resolved route reasoning reserve (migration 20260826_01, issue #1171) so
    hidden reasoning burns the reserve instead of the caller budget. The test now
    asserts the reserve-aware bound on hive-free AND an exact bound on
    deepseek-v4-flash, whose reserve is the column default of zero. The second one
    is what actually catches max_tokens being dropped, which the old single
    assertion could not distinguish from correct behaviour.
    
    The missing-Authorization-header test never reached the gateway. openai v7
    refuses to construct a client with an empty apiKey and throws locally, so the
    test asserted the SDK constructor. It now speaks raw HTTP and asserts the
    gateway 401 envelope, including that the envelope leaks no provider name.
    
    The images test wrapped its success assertions in the same try block whose
    catch asserted an APIError. A failed expect() is itself an exception, so the
    catch swallowed the suite own assertion and re-reported the real defect as a
    confusing instanceof failure. The success assertions moved out of the try.
    
    The oversized-body probe sent about 300KB of prompt. Nothing on the chat path
    rejects a body that size, so every byte was forwarded upstream and metered:
    that single line accounts for most of the 70048 tokens this run spent against
    an allowance shared with the live demo. It is now a tenth of the size and tests
    the same boundary. The job token ceiling moves from 6000 to 20000 with that
    measurement and the suite growth from 22 completions to roughly 50 written down
    next to it, as that block requires.
    
    Gateway gaps, filed and kept live as expected failures. Each uses it.fails, not
    skip: the request still goes out and every assertion still runs, and the day
    the gateway starts behaving the test passes and vitest fails the suite for an
    unexpected pass, which is the signal to remove the marker.
    
      issue #1316  n>1 answers 200 with one choice, neither honouring nor rejecting
      issue #1317  stream_options.include_usage emits no terminal usage chunk
      issue #1318  audio.speech refuses every OpenAI voice name, and 500s doing it
      issue #1319  images.generate answers 200 with an empty data array
    
    Also: the file upload path discarded the storage error entirely and answered a
    blind 500, so the files and batches failures in that run have no diagnosable
    cause anywhere in the compose logs. The error is now logged at the point of
    failure, with the customer-facing message unchanged.
